1. ОБЪЯВЛЕНИЕ КЛАССА:
  class VectorSumCalculator {
  private:
      std::vector<int> data;
      std::mutex sum_mutex;
  };

"Класс содержит вектор данных и мьютекс для защиты общей переменной.

МЬЮТЕКС (mutex = mutual exclusion) - это примитив синхронизации,
который гарантирует, что только один поток может выполнять
критическую секцию кода одновременно.

Зачем нужен мьютекс?
Без него возможна ГОНКА ДАННЫХ (race condition):
  Поток 1 читает: sum = 100
  Поток 2 читает: sum = 100
  Поток 1 пишет: sum = 100 + 50 = 150
  Поток 2 пишет: sum = 100 + 30 = 130
  Результат: sum = 130, а должно быть 180 ❌

С мьютексом:
  Поток 1 захватывает мьютекс, работает: sum = 150
  Поток 2 ЖДЁТ освобождения мьютекса
  Поток 1 освобождает мьютекс
  Поток 2 захватывает мьютекс, работает: sum = 180 ✓"

────────────────────────────────────────────────────────────────────────────────

2. ГЕНЕРАЦИЯ СЛУЧАЙНЫХ ЧИСЕЛ:
  VectorSumCalculator(size_t size) {
      data.reserve(size);
      std::random_device rd;
      std::mt19937 gen(rd());
      std::uniform_int_distribution<int> dist(1, 100);

      for (size_t i = 0; i < size; ++i) {
          data.push_back(dist(gen));
      }
  }

"Конструктор заполняет вектор случайными числами.

std::random_device - источник истинной случайности (аппаратный генератор)
std::mt19937 - алгоритм Mersenne Twister (качественный генератор)
std::uniform_int_distribution - равномерное распределение от 1 до 100

Процесс:
1. rd() даёт начальное значение (seed) для генератора
2. gen(rd()) инициализирует генератор
3. dist(gen) генерирует число от 1 до 100
4. Повторяем size раз и добавляем в вектор"

- Проходим по всем элементам вектора
- Добавляем каждый к сумме
- Возвращаем результат

Это БАЗОВАЯ ЛИНИЯ для сравнения производительности."

4. МНОГОПОТОЧНОЕ ВЫЧИСЛЕНИЕ:
  long long calculateMultiThreaded(int num_threads) {
      long long total_sum = 0;
      size_t n = data.size();
      size_t chunk_size = n / num_threads;
      size_t remainder = n % num_threads;

      std::vector<std::thread> threads;
      threads.reserve(num_threads);

"Подготовка к многопоточной работе:

1. total_sum - общая сумма (будет защищена мьютексом)
2. chunk_size = n / num_threads - размер блока для каждого потока
   Пример: 10,000,000 / 4 = 2,500,000 элементов на поток
3. remainder = n % num_threads - остаток для равномерного распределения
   Пример: 10,000,007 / 4 = 2,500,001 (остаток 3)
   Первые 3 потока получат по 2,500,002 элемента
   Последний поток получит 2,500,001 элемент"

────────────────────────────────────────────────────────────────────────────────

5. ЛЯМБДА-ФУНКЦИЯ (РАБОЧАЯ ФУНКЦИЯ ПОТОКА):
  auto worker = [this, &total_sum](size_t start, size_t end) {
      long long local_sum = 0;

      for (size_t i = start; i < end; ++i) {
          local_sum += data[i];
      }

      {
          std::lock_guard<std::mutex> lock(sum_mutex);
          total_sum += local_sum;
      }
  };

"Это ЛЯМБДА-ФУНКЦИЯ - анонимная функция, определённая на месте.

СИНТАКСИС ЛЯМБДЫ:
  [захват](параметры) { тело }

  [this, &total_sum] - СПИСОК ЗАХВАТА:
    - this - захватываем указатель на объект (для доступа к data и sum_mutex)
    - &total_sum - захватываем total_sum ПО ССЫЛКЕ (чтобы изменять)

  (size_t start, size_t end) - параметры функции

  { ... } - тело функции

АЛГОРИТМ:
1. Создаём ЛОКАЛЬНУЮ переменную local_sum = 0
   Локальная означает, что у КАЖДОГО потока своя копия
   Это избегает конкуренции за одну переменную

2. Суммируем элементы в диапазоне [start, end) в local_sum
   Здесь НЕТ конкуренции - каждый поток работает со своим диапазоном

3. КРИТИЧЕСКАЯ СЕКЦИЯ (внутри {...}):
   std::lock_guard<std::mutex> lock(sum_mutex);
   - Захватываем мьютекс (блокируем для других потоков)
   - Добавляем local_sum к total_sum
   - При выходе из блока {...} деструктор lock_guard автоматически
     освобождает мьютекс

Почему используем local_sum, а не сразу total_sum?
  - Минимизируем время удержания мьютекса
  - Без local_sum пришлось бы захватывать мьютекс 2,500,000 раз!
  - С local_sum захватываем мьютекс только ОДИН раз в конце"

────────────────────────────────────────────────────────────────────────────────

6. СОЗДАНИЕ И ЗАПУСК ПОТОКОВ:
  size_t current_start = 0;
  for (int t = 0; t < num_threads; ++t) {
      size_t current_chunk = chunk_size + (t < (int)remainder ? 1 : 0);
      size_t current_end = current_start + current_chunk;

      threads.emplace_back(worker, current_start, current_end);

      current_start = current_end;
  }

"Цикл создаёт и запускает потоки:

1. current_chunk - размер блока для текущего потока
   Первые remainder потоков получают +1 элемент

2. threads.emplace_back(worker, current_start, current_end):
   - emplace_back - создаёт объект std::thread прямо в векторе
   - Передаём лямбда-функцию worker и её аргументы
   - Поток НЕМЕДЛЕННО начинает выполнение

3. current_start = current_end - сдвигаем начало для следующего потока

Пример распределения (10 элементов, 4 потока):
  Поток 0: [0, 3)   (элементы 0, 1, 2)
  Поток 1: [3, 6)   (элементы 3, 4, 5)
  Поток 2: [6, 8)   (элементы 6, 7)
  Поток 3: [8, 10)  (элементы 8, 9)"

────────────────────────────────────────────────────────────────────────────────

7. ОЖИДАНИЕ ЗАВЕРШЕНИЯ ПОТОКОВ:
  for (auto &th : threads) {
      th.join();
  }
  return total_sum;

"join() - БЛОКИРУЮЩАЯ операция, которая ждёт завершения потока.

Что происходит:
1. Главный поток доходит до join()
2. Главный поток ОСТАНАВЛИВАЕТСЯ и ждёт
3. Когда рабочий поток завершается, join() возвращает управление
4. Главный поток переходит к следующему join()

Зачем это нужно?
Если не вызвать join(), программа может завершиться ДО того, как
потоки закончат работу, и данные будут потеряны.

После всех join() мы ГАРАНТИРОВАННО имеем правильную total_sum."

────────────────────────────────────────────────────────────────────────────────

"Эта программа реализует классический паттерн Producer-Consumer
(Производитель-Потребитель).

Один поток (производитель) генерирует числа от 0 до 99 и добавляет в очередь.

  ...
  [Потребитель 1] завершил работу
  [Потребитель 2] завершил работу
  [Потребитель 3] завершил работу

ОТКРЫТЬ: task2.cpp

1. КЛАСС ПОТОКОБЕЗОПАСНОЙ ОЧЕРЕДИ:
  template<typename T>
  class ThreadSafeQueue {
  private:
      std::queue<T> queue;
      std::mutex mutex;
      std::condition_variable cond;
      bool is_shutdown = false;
  };

"Шаблонный класс (template) - может работать с любым типом T.

КОМПОНЕНТЫ:
1. std::queue<T> - обычная очередь FIFO (first in, first out)
2. std::mutex - защищает доступ к очереди
3. std::condition_variable - УСЛОВНАЯ ПЕРЕМЕННАЯ для синхронизации
4. is_shutdown - флаг завершения работы

ЧТО ТАКОЕ УСЛОВНАЯ ПЕРЕМЕННАЯ?
Это механизм для ОЖИДАНИЯ СОБЫТИЯ:
  - Поток может ЗАСНУТЬ на условной переменной
  - Другой поток может его РАЗБУДИТЬ
  - Это эффективнее, чем бесконечный цикл проверки (busy waiting)

Пример без условной переменной (плохо):
  while (queue.empty()) {  // Цикл съедает CPU!
      // ждём...
  }

С условной переменной (хорошо):
  cond.wait(lock);  // Поток СПИТ, не тратит CPU"

2. МЕТОД PUSH (ДОБАВЛЕНИЕ В ОЧЕРЕДЬ):
  void push(T value) {
      {
          std::lock_guard<std::mutex> lock(mutex);
          queue.push(std::move(value));
      }
      cond.notify_one();
  }

"АЛГОРИТМ:

1. Блок {...}:
   std::lock_guard<std::mutex> lock(mutex);
   - Захватываем мьютекс
   - Добавляем элемент в очередь
   - При выходе из блока мьютекс автоматически освобождается

2. cond.notify_one():
   - БУДИМ ОДИН спящий поток-потребитель
   - Если все потребители спят - будим любого
   - Если все работают - ничего не делаем

Почему notify_one() ВНЕ блока?
  - Освобождаем мьютекс перед пробуждением потока
  - Иначе разбуженный поток сразу заблокируется на мьютексе
  - Это оптимизация производительности"

────────────────────────────────────────────────────────────────────────────────

3. МЕТОД POP (ИЗВЛЕЧЕНИЕ ИЗ ОЧЕРЕДИ):
  bool pop(T& value) {
      std::unique_lock<std::mutex> lock(mutex);

      cond.wait(lock, [this]() {
          return is_shutdown || !queue.empty();
      });

      if (queue.empty() && is_shutdown) {
          return false;
      }

      value = std::move(queue.front());
      queue.pop();
      return true;
  }

"Это САМАЯ СЛОЖНАЯ часть. Разберём по шагам:

1. std::unique_lock<std::mutex> lock(mutex);
   Почему unique_lock, а не lock_guard?
   - unique_lock можно ВРЕМЕННО освободить
   - cond.wait() освобождает мьютекс на время ожидания
   - lock_guard такого не умеет

2. cond.wait(lock, [this]() { return is_shutdown || !queue.empty(); });
   Это ключевая строка! Как она работает:

   a) Проверяет условие: is_shutdown || !queue.empty()
      - Если true - продолжает выполнение
      - Если false - переходит к шагу (b)

   b) АТОМАРНО (неделимо):
      - Освобождает мьютекс
      - Усыпляет поток

   c) Когда другой поток вызывает notify_one():
      - Поток просыпается
      - ЗАХВАТЫВАЕТ мьютекс
      - Возвращается к шагу (a)

   Зачем лямбда-функция?
   - Защита от ЛОЖНЫХ ПРОБУЖДЕНИЙ (spurious wakeups)
   - Поток может проснуться БЕЗ notify, нужна перепроверка

3. if (queue.empty() && is_shutdown) return false;
   - Если очередь пуста И работа завершена - выходим
   - Потребитель прекращает работу

4. value = std::move(queue.front());
   queue.pop();
   - Извлекаем элемент из очереди
   - Возвращаем true (успех)

ПОЛНЫЙ СЦЕНАРИЙ:
  Потребитель: queue.pop(value)
  Очередь пуста → wait() → поток СПИТ
  Производитель: queue.push(5) → notify_one()
  Потребитель ПРОСЫПАЕТСЯ → проверяет !queue.empty() → true → продолжает
  Извлекает value = 5"

────────────────────────────────────────────────────────────────────────────────

4. МЕТОД SHUTDOWN (ЗАВЕРШЕНИЕ РАБОТЫ):
  void shutdown() {
      {
          std::lock_guard<std::mutex> lock(mutex);
          is_shutdown = true;
      }
      cond.notify_all();
  }

"Завершение работы очереди:

1. Устанавливаем флаг is_shutdown = true под защитой мьютекса
2. cond.notify_all() - БУДИМ ВСЕ спящие потоки
   Не notify_one(), потому что нужно разбудить всех потребителей!

После этого:
  - Потребители проснутся
  - Проверят is_shutdown || !queue.empty()
  - Обработают оставшиеся элементы
  - Выйдут, когда очередь опустеет"

────────────────────────────────────────────────────────────────────────────────

5. ФУНКЦИЯ ПРОИЗВОДИТЕЛЯ:
  void producer(ThreadSafeQueue<int>& queue, int count) {
      for (int i = 0; i < count; ++i) {
          queue.push(i);
          std::this_thread::sleep_for(std::chrono::milliseconds(1));
      }
      queue.shutdown();
  }

"Производитель:
1. Генерирует числа от 0 до count-1
2. Добавляет каждое в очередь
3. Делает задержку 1 мс (имитация работы)
4. После всех чисел вызывает shutdown()

std::this_thread::sleep_for - усыпляет ТЕКУЩИЙ поток на указанное время"

────────────────────────────────────────────────────────────────────────────────

6. ФУНКЦИЯ ПОТРЕБИТЕЛЯ:
  void consumer(ThreadSafeQueue<int>& queue, int id) {
      int value;
      while (queue.pop(value)) {
          std::cout << "[Потребитель " << id << "] получил " << value << std::endl;
          std::this_thread::sleep_for(std::chrono::milliseconds(5));
      }
      std::cout << "[Потребитель " << id << "] завершил работу" << std::endl;
  }

"Потребитель:
1. Бесконечно вызывает queue.pop(value)
2. Если pop() вернул true - обрабатывает значение
3. Если pop() вернул false - выходит из цикла (shutdown)
4. Делает задержку 5 мс (имитация обработки)

Заметьте: потребитель медленнее производителя (5 мс vs 1 мс)
Поэтому нужно несколько потребителей для эффективной обработки!"

────────────────────────────────────────────────────────────────────────────────

7. СОЗДАНИЕ ПОТОКОВ В MAIN:
  ThreadSafeQueue<int> queue;

  std::thread prod_thread(producer, std::ref(queue), produce_count);

  std::vector<std::thread> consumers;
  for (int i = 0; i < num_consumers; ++i) {
      consumers.emplace_back(consumer, std::ref(queue), i + 1);
  }

  prod_thread.join();
  for (auto& th : consumers) {
      th.join();
  }

"Последовательность:

1. Создаём очередь queue

2. Создаём поток производителя:
   std::thread prod_thread(producer, std::ref(queue), produce_count);
   - std::ref(queue) - передаём ССЫЛКУ на очередь
   Зачем std::ref?
   - По умолчанию std::thread КОПИРУЕТ аргументы
   - Нам нужна одна общая очередь, не копии!
   - std::ref() говорит: передай по ссылке

3. Создаём потоки потребителей в цикле
   Каждому передаём уникальный ID (i + 1)

4. Ждём завершения всех потоков через join()

Важный момент: производитель и все потребители работают с ОДНОЙ очередью!"

ОТКРЫТЬ: task5.cpp

ПОКАЗАТЬ КОНСТРУКТОР THREADPOOL:
  ThreadPool(size_t num_threads) {
      for (size_t i = 0; i < num_threads; ++i) {
          workers.emplace_back([this]() {
              while (true) {
                  std::function<void()> task;
                  {
                      std::unique_lock<std::mutex> lock(this->queue_mutex);
                      this->condition.wait(lock, [this](){
                          return this->stop || !this->tasks.empty();
                      });
                      if (this->stop && this->tasks.empty()) {
                          return;
                      }
                      task = std::move(this->tasks.front());
                      this->tasks.pop();
                  }
                  task();
              }
          });
      }
  }

"Конструктор создаёт num_threads рабочих потоков.

Каждый поток выполняет лямбда-функцию:

1. Бесконечный цикл while (true)

2. Ждёт на условной переменной:
   condition.wait(lock, [this](){ return this->stop || !this->tasks.empty(); });
   - Спит, пока нет задач И не stop
   - Просыпается, когда появилась задача ИЛИ stop

3. Если stop И нет задач - выходит (return)

4. Извлекает задачу из очереди:
   task = std::move(this->tasks.front());
   tasks.pop();

5. Выполняет задачу: task()

6. Возвращается к шагу 1 (берёт новую задачу)

std::function<void()> - тип для хранения ЛЮБОЙ функции без параметров"

────────────────────────────────────────────────────────────────────────────────

ПОКАЗАТЬ МЕТОД SUBMIT:
  template<class F, class... Args>
  auto submit(F&& f, Args&&... args) -> std::future<decltype(f(args...))> {
      using return_type = decltype(f(args...));

      auto task = std::make_shared<std::packaged_task<return_type()>>(
          std::bind(std::forward<F>(f), std::forward<Args>(args)...)
      );

      std::future<return_type> res = task->get_future();

      {
          std::lock_guard<std::mutex> lock(queue_mutex);
          if (stop) {
              throw std::runtime_error("submit on stopped ThreadPool");
          }
          tasks.emplace([task](){ (*task)(); });
      }

      condition.notify_one();
      return res;
  }

"Это ШАБЛОННАЯ функция для добавления задачи в пул.

МАГИЯ C++ здесь на максимуме! Разберём:

1. template<class F, class... Args>
   - F - тип функции
   - Args... - ВАРИАТИВНЫЙ шаблон (любое количество типов аргументов)

2. auto submit(F&& f, Args&&... args)
   - F&& - УНИВЕРСАЛЬНАЯ ССЫЛКА (может быть lvalue или rvalue)
   - Args&&... - пакет универсальных ссылок

3. -> std::future<decltype(f(args...))>
   - Возвращает future с типом результата функции f
   - decltype(f(args...)) - автоматически определяет тип возврата

4. std::packaged_task - упаковывает функцию для получения future
   Это как std::async, но без автоматического запуска

5. std::bind - связывает функцию с аргументами
   Пример: bind(factorial, 5) создаёт функцию без параметров, которая
   вызовет factorial(5)

6. std::forward - СОВЕРШЕННАЯ ПЕРЕСЫЛКА (perfect forwarding)
   Сохраняет тип ссылки (lvalue/rvalue) при передаче

7. task->get_future() - получаем future для возврата пользователю

8. tasks.emplace([task](){ (*task)(); })
   - Создаём лямбду, которая вызовет упакованную задачу
   - Лямбда захватывает shared_ptr на task
   - Добавляем лямбду в очередь

9. condition.notify_one() - будим один спящий поток

ПРИМЕР ИСПОЛЬЗОВАНИЯ:
  auto future = pool.submit(factorial, 10);
  unsigned long long result = future.get();

Что происходит:
  1. submit упаковывает factorial(10) в packaged_task
  2. Получает future и возвращает его
  3. Добавляет задачу в очередь
  4. Будит рабочий поток
  5. Рабочий поток берёт задачу и выполняет
  6. Пользователь вызывает future.get() и получает результат"

❓ "Что такое поток и как он создаётся?"

ОТВЕТ:
"ПОТОК (thread) - это независимый путь выполнения программы.

Процесс может содержать несколько потоков. Все потоки процесса:
  - Разделяют одно адресное пространство (общая память)
  - Имеют собственный стек вызовов
  - Имеют собственный счётчик команд (program counter)
  - Выполняются ПАРАЛЛЕЛЬНО на разных ядрах CPU

Создание потока в C++:
  std::thread t(function, arg1, arg2);

  - t - объект потока
  - function - функция для выполнения
  - arg1, arg2 - аргументы функции
  - Поток запускается НЕМЕДЛЕННО

Обязательно нужно:
  - join() - ждать завершения
  - detach() - открепить поток
Иначе при уничтожении объекта thread вызовется std::terminate()!"

❓ "В чём разница между мьютексом и условной переменной?"

ОТВЕТ:
"МЬЮТЕКС (mutex) - примитив для ВЗАИМНОГО ИСКЛЮЧЕНИЯ:
  - Гарантирует, что только один поток в критической секции
  - Захват: lock()
  - Освобождение: unlock()
  - Использование: защита общих данных

УСЛОВНАЯ ПЕРЕМЕННАЯ (condition_variable) - примитив для ОЖИДАНИЯ:
  - Позволяет потоку ЗАСНУТЬ до наступления события
  - Ожидание: wait()
  - Пробуждение: notify_one() / notify_all()
  - Использование: синхронизация потоков

ОТЛИЧИЯ:
┌───────────────────┬────────────────────┬──────────────────────┐
│                   │ Мьютекс            │ Условная переменная  │
├───────────────────┼────────────────────┼──────────────────────┤
│ Назначение        │ Защита данных      │ Ожидание события     │
│ Блокирует?        │ Да, если занят     │ Да, до пробуждения   │
│ Используется с    │ Данными            │ Мьютексом + Условием │
│ Активное ожидание │ Да (spin)          │ Нет (sleep)          │
└───────────────────┴────────────────────┴──────────────────────┘

ТИПИЧНОЕ ИСПОЛЬЗОВАНИЕ ВМЕСТЕ:
  std::unique_lock<std::mutex> lock(mutex);
  cond.wait(lock, []{ return ready; });

  - Мьютекс защищает переменную ready
  - Условная переменная ждёт, пока ready не станет true"

────────────────────────────────────────────────────────────────────────────────

❓ "Что такое гонка данных (race condition)?"

ОТВЕТ:
"ГОНКА ДАННЫХ - ситуация, когда несколько потоков одновременно обращаются
к общим данным, и хотя бы один из них ПИШЕТ.

ПРИМЕР ПРОБЛЕМЫ:
  int counter = 0;

  Поток 1:              Поток 2:
  counter++;            counter++;

Кажется, что counter станет 2, но НЕТ!

Операция counter++ НЕ атомарная, она состоит из 3 шагов:
  1. Прочитать значение из памяти в регистр
  2. Увеличить регистр
  3. Записать регистр обратно в память

Что может произойти:
  Поток 1: читает counter = 0
  Поток 2: читает counter = 0
  Поток 1: вычисляет 0 + 1 = 1
  Поток 2: вычисляет 0 + 1 = 1
  Поток 1: пишет counter = 1
  Поток 2: пишет counter = 1
  Результат: counter = 1 (а должно быть 2!) ❌

РЕШЕНИЯ:
1. Мьютекс:
   std::lock_guard<std::mutex> lock(m);
   counter++;

2. Атомарные операции:
   std::atomic<int> counter;
   counter++;  // Теперь атомарно!

3. Локальные переменные (как в task1):
   Каждый поток суммирует в свою переменную, затем складываем результаты"

────────────────────────────────────────────────────────────────────────────────

❓ "В чём разница между std::thread и std::async?"

ОТВЕТ:
"std::thread:
  - Всегда создаёт НОВЫЙ поток
  - НЕ возвращает значение
  - Нужно явно вызывать join() или detach()
  - Ниже уровень абстракции

  Пример:
    std::thread t(func, arg);
    t.join();  // Обязательно!

std::async:
  - Может выполниться в НОВОМ потоке или ТЕКУЩЕМ (зависит от политики)
  - ВОЗВРАЩАЕТ std::future с результатом
  - join() вызывается автоматически при get() или уничтожении future
  - Выше уровень абстракции

  Пример:
    std::future<int> f = std::async(func, arg);
    int result = f.get();  // Автоматически ждёт

ПОЛИТИКИ ЗАПУСКА:
  std::async(std::launch::async, func, arg)
    - Гарантирует запуск в новом потоке

  std::async(std::launch::deferred, func, arg)
    - Запустится при вызове get() в текущем потоке

  std::async(func, arg)  // По умолчанию
    - Реализация выбирает сама (обычно async)

КОГДА ЧТО ИСПОЛЬЗОВАТЬ:
  - thread: когда нужен полный контроль
  - async: когда нужен результат и простота"

────────────────────────────────────────────────────────────────────────────────

❓ "Что такое ложное пробуждение (spurious wakeup)?"

ОТВЕТ:
"ЛОЖНОЕ ПРОБУЖДЕНИЕ - когда поток просыпается из condition_variable::wait()
БЕЗ вызова notify_one()/notify_all().

Это особенность реализации на уровне ОС. Может произойти из-за:
  - Сигналов UNIX
  - Оптимизаций планировщика
  - Особенностей многоядерных систем

ПРОБЛЕМА БЕЗ ЗАЩИТЫ:
  cond.wait(lock);
  // Проснулись, предполагаем, что данные готовы
  process(data);  // НО данные могут быть НЕ готовы! ❌

РЕШЕНИЕ - ПРОВЕРКА УСЛОВИЯ:
  cond.wait(lock, []{ return data_ready; });
  // Теперь ГАРАНТИРОВАННО data_ready == true ✓

Как это работает:
  while (!predicate()) {  // Проверка условия
      wait(lock);          // Ждём
  }
  // Условие точно выполнено

Библиотека делает это автоматически, если передать предикат!

БЕЗ предиката (небезопасно):
  cond.wait(lock);

С предикатом (безопасно):
  cond.wait(lock, [this]{ return !queue.empty(); });"

❓ "Зачем нужен Thread Pool, почему не создавать поток для каждой задачи?"

ОТВЕТ:
"Создание потока - ДОРОГАЯ операция:
  - Системный вызов к ядру ОС (~1000-10000 микросекунд)
  - Выделение памяти под стек (~1-8 МБ)
  - Инициализация структур данных

ПРОБЛЕМЫ БЕЗ ПУЛА:

1. НАКЛАДНЫЕ РАСХОДЫ:
   100 задач × 1 мс создания = 100 мс только на создание потоков!

2. ОГРАНИЧЕНИЕ РЕСУРСОВ:
   1000 потоков × 1 МБ стек = 1 ГБ только на стеки!

3. ПЕРЕКЛЮЧЕНИЕ КОНТЕКСТА:
   Слишком много потоков → CPU тратит время на переключение, а не на работу

ПРЕИМУЩЕСТВА ПУЛА:

1. ПЕРЕИСПОЛЬЗОВАНИЕ:
   Создали 4 потока один раз, используем для 1000 задач

2. КОНТРОЛЬ ПАРАЛЛЕЛИЗМА:
   Не больше N потоков одновременно (N = количество ядер)

3. БАЛАНСИРОВКА НАГРУЗКИ:
   Свободный поток автоматически берёт задачу

4. ЭФФЕКТИВНОСТЬ:
   Без накладных расходов на создание/уничтожение

ПРАВИЛО: Количество потоков ≈ Количество ядер CPU
  - Меньше - недоиспользуем CPU
  - Больше - бесполезные переключения контекста"

❓ "Как работает std::lock_guard vs std::unique_lock?"

ОТВЕТ:
"Оба - это RAII-обёртки для мьютекса (автоматическое освобождение).

std::lock_guard:
  - ПРОСТОЙ, лёгкий
  - Захватывает мьютекс в конструкторе
  - Освобождает в деструкторе
  - НЕ МОЖЕТ быть разблокирован досрочно
  - Не копируется, не перемещается

  Использование:
    {
        std::lock_guard<std::mutex> lock(m);
        // Критическая секция
    }  // Автоматически unlock()

std::unique_lock:
  - ГИБКИЙ, функциональный
  - Может захватить в конструкторе или позже
  - Можно вручную lock()/unlock() многократно
  - Можно временно освободить
  - Можно перемещать (но не копировать)

  Использование:
    std::unique_lock<std::mutex> lock(m);
    // Работа
    lock.unlock();  // Освобождаем досрочно
    // Другая работа без блокировки
    lock.lock();    // Захватываем снова

КОГДА ЧТО ИСПОЛЬЗОВАТЬ:

lock_guard:
  - Простая критическая секция
  - Не нужно досрочное освобождение
  - Лучше производительность (меньше накладных расходов)

unique_lock:
  - Нужно с condition_variable (wait() освобождает мьютекс)
  - Нужно досрочное освобождение
  - Условная блокировка (try_lock)

СРАВНЕНИЕ РАЗМЕРА:
  lock_guard - обычно 8 байт (только указатель на мьютекс)
  unique_lock - обычно 16 байт (указатель + флаги состояния)"

════════════════════════════════════════════════════════════════════════════════

1. ЗАБЫТЬ join():
   ❌ std::thread t(func);
      // t уничтожается → std::terminate()

   ✓ std::thread t(func);
     t.join();

2. ГОНКА ДАННЫХ:
   ❌ int counter = 0;
      // Несколько потоков: counter++

   ✓ std::mutex m;
     std::lock_guard<std::mutex> lock(m);
     counter++;

3. DEADLOCK (Взаимная блокировка):
   ❌ Поток 1: lock(m1) → lock(m2)
      Поток 2: lock(m2) → lock(m1)
      → Оба ждут друг друга вечно

   ✓ Всегда захватывать мьютексы в одинаковом порядке
     ИЛИ использовать std::lock(m1, m2)

4. ИСПОЛЬЗОВАНИЕ lock_guard С condition_variable:
   ❌ std::lock_guard<std::mutex> lock(m);
      cond.wait(lock);  // НЕ СКОМПИЛИРУЕТСЯ

   ✓ std::unique_lock<std::mutex> lock(m);
     cond.wait(lock);

5. ЗАБЫТЬ ПРЕДИКАТ В wait():
   ❌ cond.wait(lock);
      // Ложное пробуждение!

   ✓ cond.wait(lock, []{return ready;});
