ПОКАЗАТЬ ПРИВАТНУЮ СЕКЦИЮ:
  private:
      std::vector<std::unique_ptr<Client>> clients;
      std::vector<BankAccount> accounts;

"std::vector - это ДИНАМИЧЕСКИЙ МАССИВ. В отличие от обычных массивов,
его размер можно изменять во время выполнения программы.

std::unique_ptr<Client> - это УМНЫЙ УКАЗАТЕЛЬ. Это современный C++ подход
к управлению памятью:
  - unique_ptr автоматически удаляет объект, когда он больше не нужен
  - Предотвращает утечки памяти
  - Запрещает копирование (только перемещение через std::move)
  - Гарантирует, что у объекта только один владелец

Почему clients - это вектор указателей, а accounts - вектор объектов?
  - Клиенты: используем полиморфизм (Client может быть PremiumClient),
    нужны указатели
  - Счета: полиморфизм не нужен, храним объекты напрямую - эффективнее"

ПОКАЗАТЬ ПРИВАТНЫЕ МЕТОДЫ:
  private:
      Client* findClient(int id);
      BankAccount* findAccount(int accountNumber);

"Это ПРИВАТНЫЕ методы - вспомогательные функции, используемые только
внутри класса Bank. Они ищут клиента/счёт по ID/номеру и возвращают
указатель или nullptr, если не найдено."

ПОКАЗАТЬ НОВЫЙ МЕТОД accountBelongsToClient:
  bool accountBelongsToClient(int clientId, int accountNumber) const;

"Это КЛЮЧЕВОЙ метод для разграничения прав доступа!

Он проверяет, принадлежит ли счёт с номером accountNumber клиенту с ID clientId.
Возвращает true, если счёт принадлежит этому клиенту, false - если нет.

Этот метод используется в режиме клиента для проверки прав доступа перед
выполнением операций. Клиент не может работать с чужими счетами."

ПОКАЗАТЬ ПУБЛИЧНЫЕ МЕТОДЫ:
  public:
      void addClient(std::unique_ptr<Client> client);
      bool removeClient(int id);
      void deposit(int accountNumber, double amount);
      Client* getClient(int id);

"Публичные методы - это интерфейс класса, доступный извне.

addClient принимает unique_ptr по значению - это означает передачу ВЛАДЕНИЯ.
Вызывающая сторона теряет указатель, Bank становится владельцем объекта.

removeClient возвращает bool - успешность операции. Удаление может не
произойти, если у клиента есть активные счета.

getClient возвращает указатель на клиента или nullptr, если не найден.
Используется для проверки существования клиента при входе в систему."

ШАГ 6: ОБЪЯСНЕНИЕ РЕАЛИЗАЦИИ (src/Bank.cpp)
────────────────────────────────────────────────────────────────────────────────

ОТКРЫТЬ: src/Bank.cpp

ПОКАЗАТЬ МЕТОД findClient:
  Client* Bank::findClient(int id) {
      for (auto &c : clients) {
          if (c->getId() == id) {
              return c.get();
          }
      }
      return nullptr;
  }

"Этот метод ищет клиента по ID.

ЦИКЛ for (auto &c : clients) - это RANGE-BASED FOR LOOP (цикл по диапазону):
  - auto - автоматически определяет тип (здесь unique_ptr<Client>)
  - & - ссылка, чтобы не копировать указатель
  - Цикл проходит по всем элементам вектора clients

c->getId() - вызов метода через указатель (оператор ->)
  - c это unique_ptr
  - c.get() возвращает сырой указатель Client*
  - -> автоматически вызывает get() и разыменовывает

Если клиент найден - возвращаем указатель, если нет - nullptr."

────────────────────────────────────────────────────────────────────────────────

ПОКАЗАТЬ МЕТОД accountBelongsToClient:
  bool Bank::accountBelongsToClient(int clientId, int accountNumber) const {
      for (const auto &a : accounts) {
          if (a.getAccountNumber() == accountNumber && a.getClientId() == clientId) {
              return true;
          }
      }
      return false;
  }

"Этот метод реализует проверку принадлежности счёта клиенту.

Проходим по всем счетам и проверяем ДВА условия:
1. a.getAccountNumber() == accountNumber - совпадает ли номер счёта
2. a.getClientId() == clientId - принадлежит ли счёт этому клиенту

Оператор && (логическое И) означает, что ОБА условия должны быть true.

Ключевое слово const в конце метода означает, что метод НЕ ИЗМЕНЯЕТ объект Bank.
Это гарантия на уровне компиляции - компилятор не позволит изменить
поля класса внутри такого метода."

ПОКАЗАТЬ МЕТОД addClient:
  void Bank::addClient(std::unique_ptr<Client> client) {
      clients.push_back(std::move(client));
  }

"std::move - это функция, которая ПРЕОБРАЗУЕТ lvalue в rvalue.
Что это значит?

unique_ptr нельзя копировать, только перемещать.
std::move говорит компилятору: 'можно переместить содержимое этой переменной,
она больше не будет использоваться'.

После вызова std::move(client), переменная client становится пустой (nullptr).
Владение объектом передаётся в вектор clients."

ПОКАЗАТЬ МЕТОД removeClient:
  bool Bank::removeClient(int id) {
      // Проверяем активные счета
      for (auto &a : accounts) {
          if (a.getClientId() == id && a.isActive()) {
              std::cout << "У клиента есть активные счета, удаление невозможно.\n";
              return false;
          }
      }

      // Используем std::remove_if
      auto it = std::remove_if(clients.begin(), clients.end(),
                                [id](const std::unique_ptr<Client> &c) {
                                    return c->getId() == id;
                                });

      if (it != clients.end()) {
          clients.erase(it, clients.end());
          return true;
      }
      return false;
  }

"Сначала проверяем, есть ли у клиента активные счета. Если есть - нельзя удалять.

Затем используем std::remove_if - АЛГОРИТМ из стандартной библиотеки.
Как он работает:
1. Проходит по вектору
2. Применяет условие (лямбда-функцию) к каждому элементу
3. Перемещает элементы, НЕ подходящие под условие, в начало
4. Возвращает итератор на первый 'удалённый' элемент

ЛЯМБДА-ФУНКЦИЯ [id](const unique_ptr<Client> &c) { return c->getId() == id; }:
  - [id] - захват переменной id из внешней области видимости
  - (const unique_ptr<Client> &c) - параметр функции
  - { return c->getId() == id; } - тело функции
  - Возвращает true, если ID клиента совпадает с искомым

clients.erase(it, clients.end()) - удаляет элементы от it до конца вектора."

ПОКАЗАТЬ МЕТОД openAccount:
  BankAccount* Bank::openAccount(int clientId, AccountType type,
                                  double initialDeposit, const Date &openDate) {
      Client *client = findClient(clientId);
      if (!client) {
          std::cout << "Клиент не найден.\n";
          return nullptr;
      }

      BankAccount account(clientId, type, initialDeposit, openDate);
      accounts.push_back(account);
      std::cout << "Счёт успешно открыт.\n";

      return &accounts.back();
  }

"Метод создаёт новый счёт:

1. Проверяем, существует ли клиент с таким ID
2. Создаём ЛОКАЛЬНЫЙ объект BankAccount на стеке
3. push_back КОПИРУЕТ объект в вектор
4. accounts.back() возвращает ссылку на последний элемент
5. & берём адрес этого элемента и возвращаем указатель

ВАЖНО: Можно ли вернуть указатель на локальный объект?
  - НЕТ, если объект на стеке - он уничтожится после выхода из функции
  - ДА, если объект в векторе - он будет жить, пока вектор существует

Здесь объект скопирован в вектор, поэтому указатель валиден."

ПОКАЗАТЬ ФУНКЦИЮ readInt:
  int readInt() {

      while (!(std::cin >> value)) {
          std::cin.clear();

      }

"Это функция для БЕЗОПАСНОГО ВВОДА целого числа.

Как она работает:
1. std::cin >> value пытается прочитать число
   - Возвращает true при успехе, false при ошибке
2. Оператор ! инвертирует: while (!(успех)) = while (ошибка)
3. std::cin.clear() - сбрасывает флаг ошибки потока
4. std::cin.ignore(...) - очищает буфер ввода до конца строки
5. Цикл повторяется, пока не введут корректное число

Зачем это нужно?
Если пользователь введёт 'abc' вместо числа, программа не упадёт,

ПОКАЗАТЬ ГЛАВНОЕ МЕНЮ И ФУНКЦИЮ main:
  int main() {
      Bank bank;
      bool running = true;

      while (running) {
          std::cout << "\n=== Банковская система ===\n";
          std::cout << "1. Войти как сотрудник\n";
          std::cout << "2. Войти как клиент\n";
          std::cout << "0. Выход\n";

          int choice = readInt();

          switch (choice) {
              case 1: {  // Режим сотрудника
                  employeePortal(bank);
                  break;
              }

              case 2: {  // Режим клиента
                  std::cout << "Введите ID клиента: ";
                  int clientId = readInt();

                  Client *client = bank.getClient(clientId);
                  if (!client) {
                      std::cout << "Клиент не найден.\n";
                      break;
                  }

                  clientPortal(bank, clientId);
                  break;
              }

              case 0: {  // Выход
                  running = false;
                  std::cout << "Выход из программы. До свидания!\n";
                  break;
              }
          }
      }
      return 0;
  }

"Программа использует ПАТТЕРН ГЛАВНОГО ЦИКЛА с РАЗДЕЛЕНИЕМ РЕЖИМОВ:

1. Создаём объект Bank - единственный на всю программу
2. Входим в бесконечный цикл while (running)
3. Показываем ГЛАВНОЕ МЕНЮ с выбором роли
4. В зависимости от выбора:
   - case 1: вызываем employeePortal(bank) - режим сотрудника
   - case 2: проверяем ID клиента и вызываем clientPortal(bank, clientId)
5. Повторяем, пока пользователь не выберет 0 (Выход)

ВАЖНАЯ ОСОБЕННОСТЬ режима клиента:
  Client *client = bank.getClient(clientId);
  if (!client) {
      std::cout << \"Клиент не найден.\n\";
      break;
  }

Перед входом в режим клиента проверяем, существует ли клиент с таким ID.
Если нет - отказываем во входе. Это предотвращает вход несуществующих клиентов."

❓ "Что такое ООП и какие принципы вы применили?"

ОТВЕТ:
"ООП - объектно-ориентированное программирование. Я применил:

1. ИНКАПСУЛЯЦИЯ - данные скрыты в private, доступ через public методы
   Пример: поля класса Client приватны, есть геттеры/сеттеры

2. НАСЛЕДОВАНИЕ - класс PremiumClient наследуется от Client
   Пример: class PremiumClient : public Client

3. ПОЛИМОРФИЗМ - виртуальные функции для разного поведения
   Пример: virtual void displayInfo() - у PremiumClient своя реализация

4. АБСТРАКЦИЯ - скрываем детали реализации, показываем только интерфейс
   Пример: пользователь вызывает bank.deposit(), не зная как это работает"

────────────────────────────────────────────────────────────────────────────────

❓ "Зачем нужен виртуальный деструктор?"

ОТВЕТ:
"Виртуальный деструктор нужен, когда используется наследование.

Проблема без virtual:
  Client *client = new PremiumClient();
  delete client;  // Вызовется ~Client(), НЕ ~PremiumClient()
  // Утечка памяти, если у PremiumClient были выделенные ресурсы

Решение с virtual:
  virtual ~Client();
  delete client;  // Вызовется ~PremiumClient(), затем ~Client()

Правило: Если у класса есть хотя бы одна виртуальная функция,
деструктор тоже должен быть виртуальным."

────────────────────────────────────────────────────────────────────────────────

❓ "В чём разница между указателями и ссылками?"

ОТВЕТ:
"Указатель (pointer):
  - Может быть nullptr
  - Можно переприсвоить на другой объект
  - Нужно разыменовывать: *ptr
  - Синтаксис: Client *ptr = &client;

Ссылка (reference):
  - НЕ может быть null
  - Нельзя переприсвоить после инициализации
  - Автоматически разыменовывается
  - Синтаксис: Client &ref = client;

Когда что использовать:
  - Ссылки: для параметров функций (безопаснее)
  - Указатели: когда нужно nullptr или переприсваивание"

❓ "Что такое std::move и зачем он нужен?"

ОТВЕТ:
"std::move - это ПРИВЕДЕНИЕ типа, не перемещение!

Он преобразует lvalue (именованный объект) в rvalue (временный объект).

Зачем это нужно?
  unique_ptr нельзя копировать:
    unique_ptr<Client> a = ...;
    unique_ptr<Client> b = a;  // ОШИБКА компиляции!

  Но можно переместить:
    unique_ptr<Client> b = std::move(a);  // OK
    // Теперь: a = nullptr, b владеет объектом

std::move говорит компилятору: 'эта переменная больше не нужна,
можно украсть её содержимое'. Это оптимизация - вместо копирования
просто переставляем указатель."

────────────────────────────────────────────────────────────────────────────────

❓ "Зачем нужны статические члены класса?"

ОТВЕТ:
"Статический член класса существует в ЕДИНСТВЕННОМ экземпляре на весь класс,
а не у каждого объекта отдельно.

Пример:
  class Client {
      static int clientCounter;  // Один на всех
      int id;                     // У каждого объекта свой
  };

Использование:
  Client c1;  // clientCounter = 1
  Client c2;  // clientCounter = 2
  Client c3;  // clientCounter = 3

Зачем это нужно?
  - Счётчики объектов
  - Автоматическая генерация ID
  - Общие константы для класса
  - Кэширование данных

Инициализация в .cpp файле:
  int Client::clientCounter = 0;"

❓ "Почему используете std::vector, а не обычные массивы?"

ОТВЕТ:
"std::vector имеет множество преимуществ:

1. ДИНАМИЧЕСКИЙ РАЗМЕР:
   int arr[100];              // Фиксированный размер
   std::vector<int> vec;      // Можно менять размер

2. БЕЗОПАСНОСТЬ:
   arr[1000] = 5;             // Выход за границы - UB!
   vec.at(1000) = 5;          // Исключение, можно обработать

3. МЕТОДЫ:
   vec.push_back(5);          // Добавить элемент
   vec.size();                // Узнать размер
   vec.empty();               // Проверить пустоту

4. АВТОМАТИЧЕСКОЕ УПРАВЛЕНИЕ ПАМЯТЬЮ:
   - Не нужно вручную new/delete
   - Деструктор автоматически освобождает память

5. СОВМЕСТИМОСТЬ С АЛГОРИТМАМИ STL:
   std::sort(vec.begin(), vec.end());
   std::find(vec.begin(), vec.end(), value);

В современном C++ обычные массивы используются редко."

❓ "Объясните разницу между struct и class"

ОТВЕТ:
"Техническая разница ТОЛЬКО ОДНА:
  struct - члены по умолчанию public
  class  - члены по умолчанию private

То есть:
  struct Date {
      int day;  // public
  };

Эквивалентно:
  class Date {
  public:
      int day;
  };

Соглашения по использованию:
  - struct - для простых структур данных (POD типы)
    Примеры: Date, Address - только данные, минимум методов

  - class - для полноценных классов с логикой
    Примеры: Client, Bank - инкапсуляция, методы, иерархия

Это соглашение, не правило языка."

"Я реализовал систему с ДВУМЯ РОЛЯМИ: сотрудник и клиент.

АРХИТЕКТУРА:

  bool Bank::accountBelongsToClient(int clientId, int accountNumber) const {

              return true;
          }
      }
      return false;
  }

Проверяет совпадение номера счёта И ID клиента.

  if (!bank.accountBelongsToClient(clientId, accNum)) {

Это реализует принцип НАИМЕНЬШИХ ПРИВИЛЕГИЙ из информационной безопасности."

❓ "Почему при переводе не проверяется счёт получателя?"

ЛОГИКА:

Проверяется только счёт-отправитель (fromAcc).

АНАЛОГИЯ С РЕАЛЬНОСТЬЮ:
